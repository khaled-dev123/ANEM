02 Resume parser

From raw CV text to structured data

Pure Python — no NLP library required. Seven independent regex/heuristic functions each extract one field, handling French and Arabic-influenced Algerian CV conventions.

🎓

_extract_ni()

Walks a priority-ordered list of _NI_PATTERNS — regex → NI label pairs. First match wins. Covers doctorat, master, ingénieur, licence, bac+N, secondaire, moyen, primaire, sans niveau. Default: "Moyen".

→ demandeur_ni: str
📋

_extract_diplome()

Scans full text for a field-of-study keyword using _FIELD_RE: génie informatique, gestion, finance, commerce, médecine, architecture, etc. Returns first match or empty string.

→ demandeur_diplome: str
⏱️

_extract_exp_years()

Two-pass approach: first looks for explicit "N ans d'expérience" pattern. Falls back to summing all date ranges (YYYY – YYYY|présent). Capped at 40 years to match the scoring engine's normalisation ceiling.

→ demandeur_exp_years: int
💼

_extract_metier()

First checks for explicit "Poste: …" label lines via _TITLE_LINE_RE. Falls back to scanning every line for job-title keywords (ingénieur, technicien, responsable, développeur…) that are 3–10 words long.

→ demandeur_metier: str
📍

_extract_commune()

Matches adresse/ville/commune/résidence label prefixes. Falls back to scanning the full text against a hardcoded set of 43 Alger communes (_ALGER_COMMUNES). Default: "ALGER".

→ demandeur_commune: str
🌐

_extract_languages()

Checks six compiled regexes in _LANG_KEYWORDS: français/French, anglais/English (+ TOEIC/IELTS), arabe, espagnol, allemand, tamazight/berbère. Returns all matched languages.

→ languages: list[str]

Output schema

parse_resume("candidate.txt") → {
  "demandeur_ni":        "Supérieur 2",       # NI education level
  "demandeur_diplome":   "informatique",      # field of study
  "demandeur_exp_years": 3,                   # total years experience
  "demandeur_metier":    "Développeur logiciel",
  "demandeur_commune":   "CHERAGA",           # Wilaya 16 commune
  "date_inscription":    "2024-01-15",        # ISO date, today if absent
  "languages":           ["français", "anglais"],
  "source_file":         "candidate.txt",
  "raw_text":            "..."                # normalised full text
}

# record_to_features() — simplified
def record_to_features(record: dict) → np.ndarray:
  c1  = score_c1(offre_ni, demandeur_ni)
  c2  = score_c2(offre_diplome, dem_diplome, ...)
  c3  = score_c3(offre_exp_years, dem_exp_years, ...)
  c5  = score_c5(date_offre, date_inscription)
  c6  = score_c6(offre_lieu, dem_commune, scope)

  offre_exp  = min(offre_exp_years, 40) / 40.0
  dem_exp    = min(dem_exp_years,   40) / 40.0
  anc_norm   = min(anc_days, 3650)    / 3650.0

  strat_oh = _strat_onehot(strategy)     # [0,0,1,0] for S2
  ni_oh    = _ni_onehot(demandeur_ni)    # [0,0,0,0,1] for univ
  res_oh   = _residence_onehot(prox)     # [1,0,0] for same commune

  return np.array([c1, c2, c3, c5, c6,
                   offre_exp, dem_exp, anc_norm,
                   *strat_oh, *ni_oh, *res_oh],
                  dtype=np.float32)
04 Scoring engine

Six criteria, one employability score

Each criterion function is stateless, independently testable, and returns a score in [0, 1]. Combined via strategy-specific weighted average → TE ∈ [0, 100].

C1
Niveau d'instruction
score_c1(offre_ni, demandeur_ni)
NI match via 5×5 matrix lookup. Normalises both sides to canonical keys (sans/primaire/moyen/secondaire/universitaire), then reads M_NI[required][found]. Exact match → 1.0; one tier off → ~0.7.
M_NI["universitaire"]["secondaire"] = 0.6 M_NI["universitaire"]["universitaire"] = 1.0
C2
Diplômes
score_c2(offre_diplome, dem_diplome, offre_ni, dem_ni)
Three-tier heuristic on diploma strings. Falls through: exact string match → MEME SPECIALITE → first word match → MEME FILIERE → same NI tier → MEME DOMAINE → fallback AUTRES.
SPECIALITE = 1.0 · FILIERE = 0.8 DOMAINE = 0.5 · AUTRES = 0.2
C3
Expériences
score_c3(offre_exp, dem_exp, offre_metier, dem_metier)
Product of two sub-scores: M5.1 (years band match via lookup table — bands: 0, 1-2, 3-5, 6-10, 10+) × M5.2 (métier proximity: exact → 1.0, first-word → 0.7, autre → 0.3).
C3 = M5.1[years_band] × M5.2[metier_prox]
C4
Langues
score_c4()
Returns constant 1.0 — the MongoDB placement dataset contains no language fields. The weight for C4 is forced to 0 in strategy S1 so it cannot unfairly penalise secondary-level candidates.
C4 = 1.0 (constant) S1 strategy: weight_C4 = 0
C5
Ancienneté
score_c5(date_offre, date_inscription)
Computes (date_offre − date_inscription).days and maps to a stepped [0,1] score via score_anciennete(). Longer ANEM registration reflects persistent job-seeking behaviour, which historically correlates with better placement outcomes.
days = (date_offre − date_inscription) score = score_anciennete(days) → [0,1]
C6
Résidence
score_c6(offre_lieu, dem_commune, scope)
Classifies geographic proximity as: meme_commune (exact string match), meme_wilaya (commune in WILAYA_ALGER_COMMUNES set of 43 Alger communes), or autres. Looks up M_RESIDENCE[scope][proximity].
meme_commune → 1.0 meme_wilaya → 0.7 · autres → 0.3
TE = [ Σk weights[k] × scores[k] ] / Σk weights[k] × 100

classify(TE):    TE ≥ 75 → "Forte"  |  ≥ 50 → "Moyenne"  |  ≥ 25 → "Faible"  |  < 25 → "Nulle"

05 ML training loop

How the model learns from real placements

One Logistic Regression model trained per strategy on 37,358 historical placements plus synthetic negatives. LR coefficients feed back into weight overrides.

1
Fetch positive samples from MongoDB
Query the placements collection for all records — these are all real successful placements, labelled placement_success = 1. Filter per strategy using _infer_strategy(demandeur_ni).
pos = [r for r in records if infer_strategy(r["demandeur_ni"]) == strategy]
2
Generate synthetic negative samples
The dataset only contains successes — no negative examples exist. _generate_negatives() creates them by picking two random records i and j, copying record i, and replacing all demandeur_* fields with record j's values. The resulting mismatched pair is labelled 0. Ratio: 1:1 (negatives = positives).
neg = copy(positives[i]) neg["demandeur_*"] = positives[j]["demandeur_*"] neg["placement_success"] = 0
3
Build the feature matrix X
Shuffle all positives + negatives, then call build_matrix() which stacks record_to_features(r) for every record into a N × 20 float32 matrix. Labels y are 0/1.
X, y = build_matrix(pos + neg) # shape: (N, 20)
4
Train sklearn Pipeline (StandardScaler → LogisticRegression)
The pipeline first standardises every feature to zero mean / unit variance (critical for LR), then fits Logistic Regression with solver='lbfgs', class_weight='balanced', C=1.0. Cross-validated with k=5 folds.
Pipeline([ ("scaler", StandardScaler()), ("lr", LogisticRegression( max_iter=1000, C=1.0, class_weight="balanced", solver="lbfgs", random_state=42)) ])
5
Extract per-criterion importances from |coef_|
After full fit, extract lr.coef_[0] (one coefficient per feature). Take absolute values, normalise to sum=1 → per-feature importances. Map back through FEATURE_TO_CRITERION dict, averaging features that belong to the same criterion. C4 has no mapped feature → assigned placeholder 1.0.
FEATURE_TO_CRITERION = { "c1_ni_match": "C1", "c2_diplome_match": "C2", "c3_exp_match": "C3", "c5_anciennete": "C5", "c6_residence": "C6", }
6
50/50 blend → normalised weight overrides
_importances_to_weight_overrides() blends ML importances (50%) with the hand-tuned base weights (50%), normalises to sum=1. C4 is force-zeroed for S1. This prevents the model from completely overriding expert knowledge.
blended[C] = 0.5 × ml_importance[C] + 0.5 × base_weight[C] # → normalise to sum = 1.0 # → C4 = 0 if strategy == "S1"
7
Persist: MongoDB referential + local JSON cache
Weight override documents are upserted into the referential MongoDB collection (type = "ml_weight_override") and saved to ml_weight_cache.json. The DynamicScorer reads from either source, preferring MongoDB over the local cache.
push_to_mongo(results, db) # upsert to referential save_cache(results) # → ml_weight_cache.json

{

  }

06 Offer matching

From parsed resume to ranked offers

offer_matcher.py orchestrates the full scoring run: MongoDB aggregation, DynamicScorer, filtering, and ranking — returning the top-N best job matches.

fetch_unique_offers()

MongoDB aggregation pipeline groups all 37k+ placement records by (offre_ni, offre_metier, offre_lieu, offre_diplome, offre_exp_years), takes the most recent date_offre per group, and sorts by frequency descending. Returns up to 2,000 unique offer profiles.

db.placements.aggregate([
  { $group: {
    _id: {offre_ni, offre_metier, ...},
    count:      { $sum: 1 },
    date_offre: { $max: "$date_offre" }
  }},
  { $sort: { count: -1 }},
  { $limit: 2000 }
])

find_best_offers()

For each of the 2,000 offer profiles, merges offer fields with the parsed candidate fields into a single record dict, calls DynamicScorer.score(record), and collects results where TE ≥ min_score (default 25). Sorts descending, attaches rank 1..N, returns top-N.

result schema includes:
offre_* fields + employability_score
+ classification + criterion_scores
+ ml_override_active + rank

DynamicScorer — weight resolution priority

# Priority: ML overrides → base weights
DynamicScorer.from_mongo(db)   # reads referential collection
DynamicScorer.from_cache()     # reads ml_weight_cache.json
DynamicScorer._base_only()    # hand-tuned base weights fallback

# Usage
scorer = DynamicScorer.from_cache()
parsed = parse_resume("candidate.txt")
result = scorer.score_resume(parsed, offer_record)

{
  "strategy":            "S3",

  "ml_override_active":  True,

# 2. Configure MongoDB URI

# 4. Score a new .txt resume against a specific offer

    --offre-ni "Supérieur 1" \
    --offre-diplome "Génie civil" \
    --offre-exp 2 \
    --offre-metier "Ingénieur" \
    --offre-lieu "CHERAGA" \
    --date-offre "2025-06-01"

python ml_agent.py --show-weights

python ml_agent.py --demo
